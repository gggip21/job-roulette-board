# 결정 기록 (Design Decisions)

이 문서는 **메이플 직업 룰렛 현황판**을 만들면서 내린 주요 결정과 그 이유를 남긴 기록이에요.
코드와 커밋 메시지에는 "무엇을 바꿨는지"만 남아서, "왜 그렇게 했는지"를 따로 정리했어요.

- 항목마다 **상황 → 결정 → 이유 → 고려했지만 버린 안**을 적어요.
- 번호(D01…)는 바뀌지 않아요. 결정을 바꿀 때는 원래 항목을 지우지 않고 "바뀜" 표시와 새 항목 번호를 적어요. 나중에 정리한 초기 기록은 맨 앞 "0. 시작"에 D46부터 붙였어요.
- 사용자에게 보이는 변경 내역은 [`version.json`](../version.json)(사이트 맨 위 "업데이트 내역")에 있고, 이 문서는 만든 사람 입장의 기록이에요.
- 2026년 11월 12일 첫 시제품부터 11월 28일 v2.0.2까지의 기록을 바탕으로 정리했어요. 11월 25일 이후는 Claude Code 개발 대화를, 그 전(11/12~11/24)은 일반 Claude 대화와 단계별 결과 파일을 보고 정리했어요.

## 0. 시작: 개별 제작 단계 (11/12~11/24)

이 단계는 일반 Claude 대화에서 진행했어요. 그 대화 기록과 단계별 결과 파일을 같이 보고 정리했어요. 방송인 이름은 A·B·C로 적어요.

### D46. 시작: "메뉴판"이 아니라 방송 화면에 띄울 후원 현황판 (11/12)
- **상황:** 처음 요청은 "스트리머 직업 룰렛 메뉴판"이었어요. 첫 결과물은 메뉴와 가격, 실제로 돌아가는 룰렛이 있는 웹 페이지였는데, 필요한 건 그게 아니었어요. 방송 화면 위에 계속 떠 있으면서 **직업별로 모인 후원을 순위로 보여 주는 판**이 필요했어요.
- **결정:** OBS **브라우저 소스(로컬 파일)**에 넣는 **배경이 투명한 html 파일 하나**로 만들었어요. 첫 시제품은 171줄이었어요.
  - 후원이 오면 **E 키**로 편집창을 열어 직접 입력해요.
  - 표는 OBS 안(`localStorage`)에 저장해서 방송을 껐다 켜도 남아요.
  - 직업별 표 수, 확률(%), 직업군 색 막대를 보여 주고 1위를 강조해요.
- **이유:**
  - 웹에 올린 페이지는 로그인이 필요해 OBS에서 열 수 없었어요. 파일이면 어디서든 열려요.
  - 스트리머가 설치할 것 없이 파일 하나만 넣으면 돼요.
  - 이 구조가 지금까지 이어졌어요(D02, D05, D06).
- **같은 날 바로 정한 것:** 첫 방송인(A)의 공지에 맞춰 색과 규칙을 바꿨어요.
  - 2,000치즈 = 1표로 했어요.
  - 리롤 3회(5만/10만/20만)를 넣었어요.
  - 이미 키운 직업과 특수 제외 직업은 입력이 막히게 했어요.
  - 방송 세팅이 익숙하지 않은 분이라 **OBS 세팅·사용 가이드 PDF**를 처음부터 같이 드렸어요. 지금의 `GUIDE.pdf`가 여기서 시작했어요.

### D47. 방송인마다 따로 만든 현황판 (11/12~11/20)
- **흐름:**
  - **A판(11/12~11/20):** 첫 판이에요. 아래 D49~D52의 규칙이 대부분 이 판에서 나왔어요.
    - 11/13에 **메소 투표**(1억 메소 = 1표)를 넣었어요. 치즈 표와 합쳐 순위를 매기고, 하단에 치즈·메소를 따로 집계했어요.
    - 11/15에 하단 집계를 다시 배치했어요. 왼쪽에 총 득표를 두고, 오른쪽에 치즈·메소를 한 줄씩 표처럼 놓았어요. 치즈 표 수와 금액이 다른 줄에 떨어져 있어 짝이 안 맞아 보였기 때문이에요.
    - 11/20에 **디데이**와 **합산 금액 숨김**을 넣었어요.
  - **B판(11/15):** A판을 바탕으로 만들었어요. 메소 입력과 총액은 빼고, 금지 직업과 "해방" 직업(입력 불가, 회색)을 나눴어요. 좋아하는 직업에 하트를 붙였는데, 나중에 공개판의 **선호 직업**이 됐어요(D16).
  - **C판(11/16):** A판을 바탕으로 만들었어요. 직업 두 개만 1표 금액이 두 배였어요. 공개판의 **직업별 표 금액 그룹**(`spJobs`·`spMore`)이 여기서 나왔어요.
    - 리롤 여부가 정해지지 않아서 **처음엔 꺼 두고, 켜면 횟수(1~3회)와 회차별 금액을 고르게** 했어요. 공개판의 리롤 설정이 이 형태예요.
    - 하단 줄은 받은 예시 그림대로 "총 득표 · 참여 직업 · 마감 날짜와 디데이"로 바꿨어요. 금지 직업의 취소선은 굳이 필요 없어서 뺐어요.
- **결정:** 요청마다 그 방송에 맞춰 **이전 판을 복사해 고친 파일을 따로** 만들었어요. 저장 이름도 판마다 다르게 했어요. 한 PC에 두 판을 띄워도 표가 섞이지 않게 하려고요.
- **이유:** 처음엔 한두 명을 위한 도구라, 공통 구조보다 각 방송의 요구를 빨리 맞추는 게 중요했어요.
- **드러난 문제:** C판에서 금지 직업 하나를 풀어 달라는 요청이 왔어요.
  - 고칠 곳은 단어 하나였어요. 그래도 개발자가 아닌 분이 메모장으로 고치다가 따옴표나 쉼표 하나만 지워도 판이 안 떠요. 그래서 파일을 새로 만들어 드렸어요.
  - "설정 하나 바꾸는 데 만든 사람이 매번 파일을 다시 만들어야 한다"는 문제가 공개판의 **설정 페이지**(D05)로 이어졌어요.
- **남긴 숙제:** 판마다 저장 이름과 설정 형식이 달라서, 나중에 공개판으로 바꿀 때 표를 옮겨 주는 전용 업데이트 파일이 필요했어요(D06).

### D48. 하나의 공개 도구로 통합 (11/25)
- **상황:** 스트리머들 사이에서 반응이 좋아서, 누구나 쓸 수 있는 버전으로 만들어 나누기로 했어요.
- **결정:**
  - 다음 항목을 **코드 수정 없이 고르게** 했어요.
    - 이름·제목·프로필·테마 색
    - 후원 단위와 1표 금액, 직업별 예외 금액
    - 투표 불가 직업
    - 메소·리롤·디데이·총액 켜고 끄기
  - **설정은 크롬의 설정 페이지에서 고르고, 그 설정이 들어간 html 파일을 내려받는** 구조로 했어요. OBS 상호작용 창에서는 한글을 쓸 수 없어서(D49), 판 안에서 설정을 다 하게 만들 수 없었어요.
  - 방송인 그림과 메이플 공식 로고·이미지는 빼고 기본 아이콘을 썼어요.
  - 특정 방송에만 있던 특수 표시는 공개판에 넣지 않고, 기존 방송인의 전용 업데이트 파일에만 남겼어요.
- **어디에 올릴지:** 개인 사이트가 없어서 올릴 곳부터 정했어요.
  - Cloudflare Pages: 무료이고 정적 파일 요청에 제한이 없어 처음 추천안이었어요.
  - Netlify: 무료 한도를 넘으면 사이트가 멈춰서 뺐어요.
  - 집 PC 서버: 집 IP가 공개되고 PC를 끄면 사이트도 내려가서 뺐어요.
  - GitHub README: 가장 가볍지만, 스트리머에게 GitHub 화면이 낯설고 "Code → Download ZIP"을 찾기 어려워요.
  - **GitHub Pages로 정했어요(D02).** 저장소 하나로 끝나고, 개발자 화면 없이 일반 사이트처럼 보여요. 수정 기록이 남아 포트폴리오로도 쓸 수 있어요.
- **계정:** 개인 계정과 연결되지 않게 하려고 처음엔 조직 + 배포 키로 했어요. 테스트 push에서 Activity와 Actions에 개인 계정이 보였어요. 그래서 저장소와 조직을 지우고 **전용 계정**으로 다시 만들었어요(D01).
- **작업 나누기:** 파일 만들기는 일반 Claude 대화에서, 저장소 설정과 push부터는 PC의 Claude Code에서 했어요.
  - SSH 키가 PC 밖으로 나가지 않아야 했어요.
  - 지켜야 할 규칙(`gh` 금지, 커밋 작성자, 트레일러 줄 금지)은 처음부터 작업 규칙 문서로 만들어 두었어요(D03).
- **순서:** 배포를 먼저 하고, 직접 써 보며 고친 뒤 링크를 공유했어요. 다만 **주소(계정·저장소 이름)와 저장 방식은 퍼진 뒤에 바꾸기 어려워서** 공유 전에 정했어요(D06).
- **어워즈 홍보:** 만든 사람이 출품한 영상의 투표를 같이 부탁할지 정했어요.
  - 출품 영상 안에는 넣지 않았어요. 등록 뒤에는 고칠 수 없고, 외부 홍보가 들어가면 비노출될 수 있는 규정이 있었어요.
  - **현황판(방송 화면)에도 넣지 않았어요.** 다른 스트리머의 방송에 만든 사람의 홍보가 뜨게 되기 때문이에요.
  - **설정 페이지에만 조건 없는 부탁으로** 넣었어요. "투표하면 다운로드" 같은 조건 문구는 대가성 거래로 보일 수 있어서 쓰지 않아요(D42).
- **이유:** 코드 하나를 고치면 모든 사용자가 같이 좋아지게 하려고요. 이후의 버전 관리, 버튼 업데이트, 스킨도 이 통합이 있어서 가능했어요.

### D49. OBS 상호작용 창에서는 한글 입력이 안 됨 → 직업은 버튼으로 고름 (11/12)
- **상황:** 첫 판은 직업 이름을 글자로 쓰고 추천 목록에서 고르는 방식이었어요. 그런데 실제 OBS 상호작용 창에서는 문제가 셋 있었어요.
  - **한글이 써지지 않았어요.**
  - 추천 목록이 뜨지 않았어요.
  - 편집창이 길어지면 스크롤이 안 됐어요.
- **결정:**
  - 직업은 **직업군별 버튼**으로 고르고, 금액 버튼을 누르면 들어가게 했어요.
  - 버튼 옆에 지금 표 수를 붙였어요. 투표 불가 직업은 버튼에서 빼서 애초에 못 고르게 했어요.
  - 숫자는 입력되니까 금액은 직접 입력 칸에도 쓸 수 있게 했어요.
  - 한글이 필요한 제목·부제는 판 안에서 고치지 않고 파일 안 설정에서 바꾸게 했어요. 이게 나중에 설정 페이지로 이어졌어요(D05, D48).
  - 편집창은 판 위에 겹쳐 열고, 안에서 휠로 끝까지 내릴 수 있게 했어요. 닫기 버튼은 맨 위에 고정했어요.
- **이유:** 방송 중 입력은 OBS 상호작용 창에서만 할 수 있어요. 그 창의 한계 안에서 **마우스만으로 끝나야** 했어요. 지금의 입력 규칙(D11)이 여기서 시작했어요.

### D50. 2열 순위, 페이지 넘김, 좁은 폭, 공동 순위 (11/12)
- **상황:** "직업이 30~40개로 늘면 어떻게 되냐"는 질문이 나왔어요. 처음 판은 상위 10개만 보여 주고 나머지는 개수만 적었어요.
- **결정:**
  - 순위를 **2열**로 나누고, 표를 받은 직업이 한 페이지를 넘으면 **몇 초마다 다음 페이지로** 넘어가게 했어요.
  - **투표 불가 직업은 마지막 페이지에 라벨로** 모아 보여 줘요. 순위 페이지와 높이를 같게 해서 넘어갈 때 판이 들썩이지 않아요.
  - 폭이 너무 넓다는 의견에 680px → 540px → 420px로 줄였어요. **직업 이름 칸을 가장 긴 이름(6글자)에 맞추고 %를 바로 뒤에 붙였어요.** OBS 소스 너비 460이 여기서 나왔어요(D09).
  - 순위 번호는 **득표순 공동 순위**예요.
    - 10표, 10표, 3표면 1, 1, 3이에요.
    - 표가 같으면 총액이 많은 쪽이 위에 와요. 총액도 같으면 먼저 받은 쪽이 위에 와요.
  - 하단 금지 직업 목록은 마지막 페이지와 겹친다며 지웠다가, 끌 수 있는 설정이 있었다는 걸 알고 되돌렸어요. **지우지 않고 끌 수 있게** 두는 게 낫다는 기준이 이때 생겼어요.
- **이유:**
  - 방송 화면 한쪽을 차지하는 판이라 작아야 해요.
  - 많은 직업을 다 보여 주려면 페이지를 넘겨야 했어요.
  - 공동 순위는 시청자가 "같은 표인데 순위가 다르다"고 오해하지 않게 해 줘요.

### D51. 파일 전달 방법: 영문 파일 이름, 한 폴더, "현재 페이지 새로 고침" (11/12~11/20)
- **상황:**
  - 드라이브로 zip을 전달했더니 **PDF가 자꾸 빠졌어요.** 파일 이름이 한글이라 일부 압축 프로그램에서 깨진 것으로 봤어요.
  - 수정판을 덮어쓸 때 표가 남는지 묻는 질문이 나왔어요.
  - 한 방송인은 OBS를 켤 때마다 링크를 다시 넣어야 했어요.
- **결정:**
  - zip 안의 **파일 이름을 모두 영문**으로 했어요. 풀면 영문 폴더 하나로 나오게 묶었어요(지금의 `job-roulette-board/` 폴더).
  - 수정판은 **같은 폴더에 같은 이름으로 덮어쓰고, OBS 소스 속성에서 "현재 페이지 새로 고침"**을 누르게 했어요. 바로 아래 **"캐시 새로 고침"은 표가 지워질 수 있어서 누르지 말라고** 매번 적었어요. 이 안내는 지금 가이드에도 있어요(D07).
  - 링크 문제의 원인은 두 가지로 좁혔어요. 압축 프로그램의 임시 폴더에서 연 경우와, URL 칸에 `file:///` 주소를 붙여 넣은 경우예요. 그래서 **반드시 "로컬 파일" 체크 + 찾아보기로** 연결하게 안내했어요.
- **알게 된 것:**
  - 표는 html 파일이 아니라 OBS 브라우저 저장공간에 있어요. 그래서 로컬 파일이면 위치가 바뀌어도 남아요.
  - 하지만 **URL 칸으로 연 파일과 로컬 파일로 연 파일은 저장공간이 따로**예요. 연결 방식을 바꾸면 빈 판으로 보일 수 있어요.
  - 그래서 저장 이름을 바꾸지 않는 것만큼이나, 파일을 여는 방법을 한 가지로 정해 안내하는 게 중요했어요(D06).

### D52. 후원 자동 연동은 처음부터 보류 (11/12)
- **상황:** 후원이 오면 손으로 넣어야 해서, 방송 플랫폼 후원 API와 연동할 수 있는지 알아봤어요.
- **알아본 것:**
  - 공식 API에 후원 이벤트가 있어서 금액과 메시지를 받을 수 있어요. 다만 일부 후원 종류는 빠질 수 있었어요.
  - 앱 등록과 비밀 키, 토큰 갱신과 재연결이 필요해요. 그래서 **html 파일 하나로는 안 되고, PC에 중계 프로그램을 같이 켜야** 해요.
  - 후원 메시지는 자유롭게 쓰여서(줄임말, 오타, 직업 두 개) 직업을 100% 자동으로 알아보기 어려워요.
  - 가장 큰 벽은 **스트리머 쪽 세팅**이었어요. OBS 세팅도 어려워하는 분들에게 앱 등록과 프로그램 실행까지 맡기기는 어려웠어요.
- **결정:** 수동 입력을 유지했어요. 나중에 한다면 반자동을 추천안으로 남겼어요. 후원이 대기 목록에 뜨고, 스트리머는 [적용]만 누르는 방식이에요.
- **버린 안:** 로그인 쿠키를 쓰는 비공식 API는 쓰지 않아요. 플랫폼이 허락하지 않았고, 스트리머 계정이 보호조치될 수 있어요.
- 공개판에서도 같은 이유로 보류 중이에요(D43).

## A. 운영·배포

### D01. 저장소는 전용 GitHub 계정 하나로만 운영
- **상황:** 저장소 주인의 개인 계정이 커밋·Activity·배포 기록에 드러나지 않아야 했어요. 처음에는 조직(organization)을 만들고 저장소에 **배포 키(Deploy key)**를 달아 push했어요. 그런데 로그인하지 않은 창으로 기록을 확인해 보니, 배포 키를 등록한 개인 계정이 Activity에 나왔어요.
- **결정:** 그 시도를 중단하고 저장소를 지운 뒤, **전용 계정(`gggip21`)** 아래에 새로 만들었어요. 그리고 그 **계정의 SSH 키**로만 push해요.
  - 커밋 작성자는 저장소 로컬 설정의 noreply 주소예요.
  - push할 때마다 연결 계정, 작성자, 원격 주소를 확인해요.
  - push한 뒤에는 로그인 없이 Activity를 확인해요.
- **이유:** 배포 키는 그 키를 등록한 사람의 계정으로 기록에 남아요. 계정 SSH 키는 그 계정 이름으로만 남아요.
- **버린 안:** 조직 + 배포 키(위 이유), GitHub CLI(`gh`)로 저장소 관리(이 PC의 `gh`는 다른 계정으로 로그인돼 있을 수 있음).

### D02. 서버 없이 GitHub Pages 정적 사이트 + 파일 하나
- **결정:** 설정 페이지와 현황판을 모두 정적 파일로 만들어 GitHub Pages로 배포해요. 현황판은 **html 파일 하나**로 OBS에 넣어요. 다운로드 zip도 Releases가 아니라 `download/` 폴더에서 바로 링크해요.
- **이유:**
  - 서버 운영 비용과 관리 부담이 없어요.
  - 스트리머는 "파일 하나 받아서 OBS에 넣기"만 하면 돼요.
  - 투표 기록이 밖으로 나가지 않아요.
  - Releases는 작성자 프로필이 보여서 쓰지 않았어요.
- **버린 안:** 서버형 웹앱(로그인·DB). 실시간 자동 집계 같은 기능엔 유리하지만, 운영 부담과 개인정보 문제가 커요(D43 참고).

### D03. 커밋 메시지는 한 줄, 작업 규칙 문서는 저장소에 올리지 않음
- **결정:** 커밋 메시지는 한국어 한 줄 요약이고, 트레일러(공동 작성자 줄 등)는 넣지 않아요. 작업 규칙 문서(`CLAUDE.md`)는 `.gitignore`로 저장소에서 빼요.
- **이유:** 공개 기록에 다른 이름이나 도구 정보가 섞이지 않게 하려고요. 대신 "왜"는 이 문서에 모아요.

### D04. push할 때마다 배포 결과를 확인
- **결정:** push한 뒤 이 세 가지를 확인해요.
  1. 사이트에 올라간 파일을 받아 **커밋한 파일과 해시(SHA-1)가 같은지** 비교해요.
  2. 비공개여야 할 파일(`CLAUDE.md`)이 404인지 봐요.
  3. Activity에 전용 계정만 나오는지 봐요.
- **이유:** GitHub Pages는 반영이 늦거나 캐시가 남을 수 있어요. "올렸다"와 "사용자가 받는다"가 같은지 확인하는 단계예요.

## B. 현황판 구조

### D05. 설정은 파일 안의 JSON 한 곳, 사이트는 그 부분만 바꿔서 내려줌
- **결정:** 현황판의 모든 설정(제목, 단위, 표 금액, 투표 불가 직업, 테마, 스킨 등)은 `<script id="board-config" type="application/json">` 한 곳에 있어요. 설정 페이지는 배포된 현황판을 **템플릿으로 받아 이 JSON만 바꿔** 파일을 만들어요.
- **이유:**
  - 현황판 코드는 하나만 관리하면 돼요.
  - 설정 페이지와 실제 파일이 항상 같은 버전이에요.
  - 설정 페이지 미리보기도 같은 템플릿을 그대로 띄워서, 미리보기와 받은 파일이 똑같이 보여요.
- **버린 안:** 설정 페이지에서 현황판 코드를 직접 조립(코드가 두 벌이 됨), 설정을 별도 파일로 분리(OBS에 파일 두 개를 넣어야 함).

### D06. 투표 기록은 OBS 안(localStorage)에, 저장 이름은 절대 바꾸지 않음
- **결정:** 표는 파일이 아니라 OBS 브라우저 소스의 `localStorage`에 `mapleJobRouletteBoard.v1`이라는 이름으로 저장해요. 이 이름은 바꾸지 않아요.
- **이유:** 이름이 바뀌면 예전 표를 못 읽어 0표로 보여요. 실제로 초기에 개별 제작했던 현황판들은 저장 이름이 제각각이었어요. 그래서 공개 버전으로 덮어쓰면 표가 0으로 보였고, 그분들께는 예전 표를 한 번 옮겨 주는 **전용 업데이트 파일**을 따로 만들어 드렸어요(이 파일은 개인 정보가 들어 있어 공개 저장소에 넣지 않았어요).
- **같이 지키는 것:** 설정에 새 항목을 추가할 때 예전 키 이름은 바꾸지 않아요. 파일에 없는 항목은 기본값(`DEF`)과 합쳐서 채워요. 그래서 예전 파일도 새 버전에서 열려요.

### D07. 설정을 바꿀 땐 "다시 받아 같은 파일에 덮어쓰기 + 판 새로 고침"
- **상황:** 처음 설정을 잘못한 스트리머가 다시 받은 파일을 OBS에 바로 적용하지 못해 헤맸어요. 소스를 다시 넣어야 하는 줄 알았어요.
- **결정:**
  - 사이트에서 다시 받은 파일을 **같은 이름으로 덮어쓰고**, 편집창의 **판 새로 고침**을 누르면 방송 중에도 바로 적용돼요.
  - 설정 페이지는 브라우저의 파일 저장 창(`showSaveFilePicker`)으로 **기존 파일을 골라 바로 덮어쓰게** 했어요. 그래서 다운로드 폴더에 `roulette-board (1).html`이 생기는 일을 줄였어요.
  - "파일 설정 불러오기"로 예전 파일의 설정을 다시 불러와 고칠 수 있어요.
- **이유:** 표는 OBS 안에 있으니 파일을 바꿔도 표는 남아요(D06). 다만 **표 금액을 바꾸면** 쌓인 금액 기준으로 표 수가 다시 계산된다는 점은 안내했어요.

### D08. 편집창에서 바꾼 값과 파일 값이 부딪힐 때의 규칙
- **상황:** 투명도, 표시 항목, 스킨, 제목처럼 받은 뒤에도 편집창에서 바꿀 수 있는 값이 있어요. 그런데 나중에 사이트에서 다시 받아 덮어쓰면 어느 쪽을 써야 할지 애매해요.
- **결정:** 편집창에서 바꾼 값은 `{v: 바꾼 값, base: 그때 파일 값}`으로 저장해요. 파일 값이 `base`와 달라졌으면(즉 사이트에서 새로 설정해 받았으면) **새 파일 값을 우선**하고, 편집창 값은 버려요.
- **이유:** "방송 중 잠깐 바꾼 값"과 "사이트에서 일부러 다시 설정한 값"을 구분할 수 있어요. 사이트에서 다시 받은 쪽이 더 최근의 의도라고 봤어요.

### D09. OBS 소스 크기는 판이 직접 재서 알려 줌, 기본 460 × 510
- **상황:** 처음엔 크기를 고정(460 × 700)으로 안내했어요. 그런데 투표 불가 직업 수, 리롤, 디데이에 따라 판 높이가 달라져 잘리거나 남았어요.
- **결정:** 현황판의 `needSize()`가 **가장 길어지는 경우**까지 넣어서 실제 판을 재요(리롤 칸, 디데이 "집계 완료", 가장 긴 금액 숫자). 그 크기를 편집창과 설정 페이지에 보여 줘요. OBS 창이 작으면 편집창에 경고가 떠요.
- **이유:** OBS 속성 숫자는 파일이 대신 바꿀 수 없어요. 그래서 "정확한 숫자를 알려 주는 것"이 최선이에요. 미리 최악의 경우를 넣어 두면 나중에 표가 늘거나 추첨 모드로 바뀌어도 판이 잘리지 않아요.

### D10. 크기 배율은 판 전체를 확대, 잘림 방지
- **상황:** 크기 배율을 1보다 키우면 판 아래가 잘렸어요(배포 중이던 버전에도 있던 문제).
- **결정:** `overflow: hidden`을 `html`이 아니라 `body`에만 걸었어요.
- **이유:** OBS 기본 CSS도 body에 hidden을 넣어요. html에 걸면 확대된 판이 body 높이에서 잘려요.

## C. 입력·추첨

### D11. 입력은 마우스로 끝나게
- **상황:** 스트리머는 OBS **상호작용 창**에서 마우스로 조작하는 경우가 많았어요.
- **결정:**
  - 직업 버튼과 +1/+5/+10표 버튼을 넣었어요.
  - 금액 칸 양옆에 − + 버튼을 두고, 한 번에 **고른 직업의 표 금액**만큼 움직이게 했어요.
  - 꾹 누르면 1칸 → 5칸 → 10칸씩 빨라져요.
  - 직접 적은 금액이 단위에 안 맞으면 가까운 단위로 맞춰요.
  - 금액 초기화 버튼도 있어요.
  - "한글이 안 써져요" 같은 키보드 문제 안내는 클릭으로 다 되니 뺐어요.
- **이유:** 키보드 포커스 문제를 피하고, 후원이 몰릴 때 빠르게 입력할 수 있어요.

### D12. 핀볼 추첨용 복사 형식 `직업*표`
- **결정:** 집계 결과를 `아란*6,에반*4`처럼 복사해 핀볼 추첨 사이트에 바로 붙여넣게 했어요.
  - 1표 이상인 직업만 나오고, 투표 불가 직업은 빠져요.
  - `아크메이지(썬,콜)`처럼 이름에 쉼표가 있는 직업은 `썬콜`, `불독`으로 내보내요.
  - 직업 줄여 쓰기를 켜도 복사 텍스트는 원래 이름이에요(D18).
- **이유:** 이름 속 쉼표 때문에 핀볼에서 직업이 둘로 나뉘는 문제를 막으려고요. 실제 추첨 사이트에서 붙여넣기가 되는 것을 확인했어요.

### D13. "집계 완료 · 추첨 시작" 모드
- **상황:** 리롤은 보통 디데이에 투표를 다 받은 뒤 추첨할 때 써요. 그래서 처음부터 리롤 칸이 "1회 사용" 상태로 보이는 건 어색했어요.
- **결정:** 편집창 맨 위에 **집계 완료 · 추첨 시작** 버튼을 뒀어요. 누르면 이렇게 돼요.
  - 편집창이 닫히고, 판 제목이 "추첨 시작"과 **남은 리롤 횟수**만 크게 보이게 바뀌어요.
  - 리롤 칸이 모두 미사용으로 시작하고, **판의 칸을 직접 눌러** 사용 처리해요.
  - 추첨용 텍스트 창이 판 가운데에 뜨면서 자동으로 복사돼요.
  - 리롤 금액 모으기: 칸 위에서 +/−로 모으고, 다 모이면 자동으로 사용 처리돼요. 한 번에 더하는 단위는 보통의 최소 후원 단위예요(원·치즈 1천, 별풍선 10개).
- **이유:** 투표 단계와 추첨 단계에서 판이 보여 줘야 할 정보가 달라요. 추첨 단계에서는 표 금액 안내 대신 리롤 상황이 중요해요.

### D14. 판에서 바로 입력, 마우스를 올린 동안 순위 고정
- **결정:**
  - 판의 순위 줄에 마우스를 올리면 표 수 양옆에 −/+가 나와 1표씩 넣고 빼요.
  - 표가 없을 땐 가운데 +로 편집창을 열어요.
  - **마우스가 판 위에 있는 동안은 순위 정렬과 페이지 넘김을 멈춰요.**
- **이유:** 누르는 사이에 줄이 다른 순위로 움직이면 엉뚱한 직업을 누르게 돼요. 버튼이 표 수를 가리지 않도록 위치도 조정했어요.

### D15. 클릭·휠로 바로 페이지 넘김
- **결정:** 판을 클릭하거나 휠을 굴리면 바로 다음(이전) 페이지로 넘어가요. 아래 점을 누르면 그 페이지로 가요. 마우스가 판을 떠나면 자동 넘김 시간을 처음부터 다시 세요.
- **이유:** 방송 중 특정 순위를 바로 보여 주고 싶을 때가 있어요. 손을 뗀 직후에 바로 넘어가면 어색해서 시간을 다시 세요.

## D. 표시·가독성

### D16. 투표 불가 → 선호 직업, 한 버튼으로 순환
- **결정:** 설정 페이지에서 직업을 누를 때마다 **없음 → 투표 불가 → 선호 → 없음**으로 바뀌어요. 투표 불가는 입력 자체가 막히고, 선호는 판에 하트로 표시만 돼요. 판 아래 표시와 "페이지 표시"는 각각 켜고 끌 수 있고, 받은 뒤에도 편집창에서 바꿀 수 있어요.
- **이유:** 버튼을 따로 두면 화면이 복잡해져요. 같은 직업이 투표 불가이면서 선호일 수는 없으니 한 버튼으로 순환시켜도 돼요.

### D17. "다운 후 변경 가능" 태그는 붙이고, "변경 불가" 태그는 붙이지 않음
- **결정:** 받은 뒤 편집창에서 바꿀 수 있는 항목(표시, 스킨, 색, 제목·부제, 리롤 표시)에만 **다운 후 변경 가능** 태그를 달아요. 설정 맨 위에 태그 설명 한 줄을 넣었고, 이 줄은 OBS·프릭샷 선택에 따라 바뀌어요.
- **이유:** 태그가 없는 항목도 "다시 받아 덮어쓰기"로 바꿀 수 있어요. "변경 불가"라고 쓰면 한 번 받으면 못 바꾸는 줄 알고 겁먹을 수 있어요. 또 모든 칸에 태그가 붙으면 정작 중요한 태그가 안 보여요.

### D18. 직업 이름 줄여 쓰기 (목록은 만든 사람이 검수)
- **결정:** 데몬슬레이어 → 데슬, 엔젤릭버스터 → 엔버처럼 판에서만 줄여 쓰는 옵션이에요. 줄임말 목록은 만든 사람이 직접 검수했어요(다크나이트 → 닥나, 캐논마스터 → 캐슈, 블래스터 → 블래로 수정). 편집창 버튼과 추첨 복사 텍스트는 원래 이름이에요.
- **이유:** 게임 커뮤니티에서 실제로 쓰는 줄임말이어야 어색하지 않아요. 추첨 텍스트는 다른 사이트에 붙여넣는 거라 정확한 이름이 안전해요.

### D19. 글씨는 칸 크기를 유지한 채 최대한 크게
- **상황:** "글씨가 작다"는 피드백이 있었어요.
- **결정:**
  - 줄 높이(42px)와 칸 크기는 그대로 둬요.
  - 직업 이름은 **20px에서 시작해 긴 이름만 한 줄에 맞을 때까지 줄여요.**
  - 줄여 쓰기를 켜면 이름이 짧아진 만큼 **표 수·퍼센트도 크게** 나와요.
  - 이름이 정말 안 들어가는 페이지만 숫자 크기를 한 단계 낮춰요.
  - 손글씨처럼 작아 보이는 글꼴의 스킨은 이름 크기에 배율을 곱해요.
- **이유:** 칸을 키우면 판 크기가 바뀌어 기존 OBS 설정이 깨져요(D29). 숫자를 더 키워 보는 실험도 했는데, 긴 이름 때문에 오히려 숫자가 작아지는 페이지가 생겨 원래대로 되돌렸어요.
- **버린 안:** 줄여 쓰기를 끈 상태에서도 숫자까지 키우기(긴 이름이 13px 아래로 줄거나 두 줄이 되어 더 읽기 어려움).

### D20. 기본 배경 투명도 75% → 100%
- **결정:** 처음엔 게임 화면이 비치는 75%가 기본이었어요. 스킨이 생긴 뒤 **새로 받는 파일은 100%(불투명)**로 바꿨어요. 이미 받은 파일은 각자 값 그대로예요.
- **이유:** 스킨마다 다른 판 바탕(체크·노트·별밤 등)이 잘 보여야 차이가 드러나요. 투명하게 쓰고 싶은 사람은 편집창에서 바로 바꿀 수 있어요.

### D21. 화면·문서에 이모지를 쓰지 않음
- **결정:** 아이콘은 모두 직접 그린 SVG예요(선 아이콘, 스킨 고르기 그림 아이콘 포함).
- **이유:** 이모지는 PC·OS마다 모양이 다르고, OBS나 오래된 PC에서는 네모로 깨질 수 있어요. 색이 버튼 글자색을 따라가게 만들 수도 없어요.

## E. 업데이트

### D22. 버전과 업데이트 내역은 `version.json` 하나를 같이 읽음
- **상황:** 사용자가 늘면서 "수동 업데이트"라 무엇이 바뀌었는지 알리기 어려워졌어요.
- **결정:** `version.json`에 버전별 날짜·제목·항목을 적어요.
  - 설정 페이지는 맨 위에 최신 버전 한 줄과 펼치는 내역을 보여 줘요.
  - 현황판은 같은 파일을 읽어 새 버전이 있는지 확인해요.
  - 날짜 옆에는 "오늘·어제·n일 전"을 강조해서 보여 줘요(지금 시각 기준).
- **이유:** 한 파일만 고치면 사이트와 판이 같이 알게 돼요. 현황판은 이 파일을 **읽기만** 하고, 아무것도 보내지 않아요.

### D23. 새 버전 알림은 판 위에 크게, 한 번 닫으면 다음 버전까지 안 뜸
- **상황:** 처음엔 방송 화면에 노출되지 않게 **편집창 안에만** 알림을 넣었어요. 하지만 스트리머가 알림을 못 보고 지나칠 수 있었어요.
- **결정:** 판 가운데에 큰 업데이트 창을 띄워요. **닫기를 누르면 다음 버전까지 다시 안 떠요.** 편집창 맨 위에도 같은 내용이 있어요. 창이 판보다 길면 내용만 스크롤되고 버튼은 항상 보여요.
- **트레이드오프:** 닫기 전까지는 시청자에게도 보여요. 그 대신 놓치지 않는 쪽을 골랐어요.

### D24. 버튼 업데이트: 최신 코드를 OBS 안에 저장해 iframe으로 실행
- **상황:** 현황판은 스트리머 PC에 있는 파일이에요. OBS 안의 웹페이지는 그 파일을 덮어쓸 권한이 없어요.
- **결정:**
  1. "지금 업데이트"를 누르면 사이트의 최신 `roulette-board.html`을 받아 `localStorage`(`mapleJobRouletteBoard.code`)에 저장해요.
  2. 다음 실행부터 파일 맨 앞의 작은 **로더**가 저장해 둔 코드가 파일보다 새것인지 봐요.
  3. 새것이면 그 코드에 **파일의 설정(JSON)을 끼워 넣어** 화면 전체 크기의 `iframe(srcdoc)`으로 띄워요. 원래 파일의 나머지는 실행하지 않아요.
  4. 표는 같은 저장소(같은 출처)를 써서 그대로예요.
  5. 새 코드가 실행 신호를 보내지 않으면 그 버전을 **막고**(`...codeBad`) 원래 파일 버전으로 다시 띄운 뒤 안내해요. iframe 로딩이 끝났는데 신호가 없거나 15초가 지나면 실패로 봐요.
  6. 편집창에 "원래 파일 버전으로 되돌리기" 버튼이 있어요.
- **이유:**
  - 파일을 못 고치는 환경에서 "버튼 하나 업데이트"를 하는 방법이에요.
  - 인터넷이 끊겨도 저장해 둔 코드로 실행돼요.
  - 잘못된 버전을 push해도 각 PC에서 자동으로 원래 버전으로 돌아와요.
- **버린 안:**
  - `document.write`로 문서를 통째로 바꾸기: 요즘 브라우저는 전역 범위가 유지돼서, 같은 `const`를 다시 선언하면 오류가 나요.
  - `blob:` 주소로 이동: 출처가 달라져 저장된 표를 못 읽을 수 있어요.
  - 열 때마다 항상 사이트에서 최신 코드 받기: 인터넷이나 GitHub가 안 될 때 판이 안 떠요. 또 잘못 올린 코드가 모든 방송에 즉시 퍼져요.
- **주의:** push하면 버튼을 누른 스트리머 모두에게 바로 가요. 그래서 현황판은 반드시 로컬에서 동작을 확인한 뒤 push해요.

### D25. 정식 패치와 마이너 패치, 수정 번호
- **결정:** 버전 번호(`BOARD_VER`) 말고 **수정 번호(`BOARD_BUILD`)**를 따로 둬요. 현황판을 push할 때마다 1씩 올려요.
  - **정식 패치:** 버전 번호를 올려요. OBS를 켤 때 판에 업데이트 창이 떠요.
  - **마이너 패치:** 버전 번호는 그대로이고 수정 번호만 올려요. 판에서 **새로 고침**을 눌렀을 때만 "작은 수정이 있어요" 창이 떠요. 사이트 내역에는 "마이너 패치" 태그가 붙어요.
  - **새로 고침 = 업데이트 확인:** 새로 고침을 누르면 판을 다시 읽은 뒤 정식 → 마이너 → 최신 순으로 알려 줘요. 정식 패치는 전에 닫았어도 다시 보여 줘요.
- **이유:** 작은 수정 때마다 모든 방송에 업데이트 창을 띄우면 귀찮아요. 그렇다고 아예 못 받게 하면 버그 수정이 늦게 퍼져요. "직접 확인한 사람에게만" 알리는 게 중간 지점이에요.

### D26. 버전 번호를 매기는 기준
- **결정:**
  - 스킨처럼 판이 크게 바뀌는 업데이트는 **2.0**으로 올렸어요. 홍보할 때 알아보기 쉬워서예요.
  - 가독성 개선처럼 작은 개선은 **2.0.x**로 올렸어요.
  - 아주 작은 변경은 버전을 올리지 않고 다음 정식 버전에 묶었어요. 예를 들어 새로 고침 아이콘은 2.0.1 상태로 먼저 올렸다가 2.0.2 내역에 넣었어요.
- **이유:** 버전 비교는 숫자 단위로 해서 "2.0.1 > 2.0"이 제대로 잡혀요. 업데이트 창은 버전이 오를 때만 뜨니, 버전을 올리는 빈도가 곧 알림 빈도예요.

## F. 스킨·이벤트

### D27. 판 구성은 그대로, 꾸밈만 바꾸는 스킨 12종
- **상황:** "판 모양이 다른 테마"(룰렛 원판, 한 줄 큰 글씨 등)와 "꾸밈만 다른 스킨" 중에 골라야 했어요.
- **결정:** 구성(순위 줄, 리롤, 하단)은 그대로 두고 스킨만 바꿔요.
  - 크리스마스, 겨울 눈, 레트로 픽셀, 새해·설날, 봄 벚꽃, 여름 바다, 할로윈, 가을 단풍, 네온 사이버, 별밤·우주, 종이·다이어리, 유리, 이렇게 12종이에요.
  - 처음엔 색과 장식만 달랐는데 "스킨끼리 차이가 작다"는 의견이 있었어요. 그래서 스킨마다 아래를 모두 다르게 했어요.
    - 글꼴, 순위 배지, 1위 장식
    - 줄·막대 모양, 막대 무늬
    - 프로필 테두리, 리롤 칸, 페이지 점
    - 하단 상자, 페이지 넘김 효과, 판 바탕 무늬
    - 표가 들어올 때 효과(눈·꽃잎·금화·"+1" 등)
- **이유:** 기능이 같아야 사용법을 다시 배울 필요가 없고, 업데이트·크기 계산도 하나로 유지돼요. 방송마다 다르게 보이는 건 꾸밈만으로도 충분했어요.
- **버린 안:** 판 구조가 다른 테마(테마마다 크기 계산·입력 방식이 달라져 관리가 크게 늘어남).

### D28. 기본 스킨만 색을 고를 수 있음
- **결정:** 기본이 아닌 스킨은 **스킨 색으로 고정**해요. 설정 페이지와 편집창 모두 기본 스킨일 때만 색 선택이 보여요.
- **이유:** 스킨은 장식 색과 판 색이 맞물려 있어요. 아무 색이나 고르면 어색해지기 쉬워요. 색을 고르고 싶은 사람은 기본 스킨을 쓰면 돼요.

### D29. 어떤 스킨이든 판 크기는 같게 (460 × 510)
- **결정:** 스킨 장식은 판 위나 뒤에 겹쳐 그리고 레이아웃을 밀지 않아요.
  - 크리스마스 전구 줄 때문에 판이 10px 길어진 것을 되돌렸어요.
  - 손글씨 글꼴 때문에 하단 줄이 꺾이던 것을 줄 높이 고정과 글씨 크기 제한으로 막았어요.
  - 스킨 12종 × 디데이·총 금액 켬/끔에서 크기를 자동으로 확인했어요.
- **이유:** 버튼 업데이트로 스킨이 바뀌어도 기존 OBS 소스 크기(510)에서 판 아래가 잘리면 안 돼요.

### D30. 가독성 검수 후 조정
- **결정:** 모든 스킨을 2배로 확대해 검수하고 아래를 고쳤어요.
  - 크리스마스 줄무늬를 옅게 했어요.
  - 할로윈·종이·벚꽃의 이름을 키우고 그림자를 넣었어요.
  - 별밤 혜성 빛을 작게 했어요.
  - 할로윈·벚꽃의 작은 글씨(규칙, 리롤 칸 등)는 기본 글꼴로 바꿨어요.
  - 리롤 칸의 회차 글씨를 흰색 굵은 글씨 + 그림자로 바꿨어요. 크리스마스는 리본을 옅게 하는 안(4개 중 D안)을 골랐어요.
- **이유:** 꾸밈이 강해질수록 숫자가 묻혀요. 방송 화면에서는 작은 글씨가 더 안 보여요.

### D31. 크리스마스 이벤트: 2.0 전 판에만, 색은 그대로, 끝나는 날짜 없음
- **결정:** 2.0 업데이트 때 **2.0 전에 받은 파일**(설정에 `skin` 항목이 없는 파일)에만 크리스마스 장식을 씌워요.
  - 색은 원래 쓰던 색을 유지해요.
  - 사이트 미리보기, 새로 받는 파일, 기본 zip은 기본 그대로예요.
  - 편집창 맨 위 "끄기"를 누르면 꾸미기 탭으로 가고, 스킨을 바꾸면 꺼져요.
  - 끝나는 날짜는 넣지 않았어요.
- **이유:**
  - "업데이트 기념 이벤트"로 기존 사용자에게 변화를 보여 주려는 목적이었어요. 처음엔 사이트 기본까지 바뀌었는데 의도와 달라 범위를 좁혔어요.
  - 원래 색을 유지해야 방송마다 쌓아 온 판의 개성이 지켜져요. 7가지 색 모두 크리스마스 장식과 어울리는지 샘플로 확인했어요.
  - 숨은 종료 날짜는 "싫은 사람은 바로 꾸미기 탭에서 바꾼다"는 판단으로 넣지 않았어요.
- **끝낼 때:** 코드의 `EVENT`와 설정 페이지 안내(`#evHint`)를 같이 지우고 정식 패치로 올려요.

### D32. 움직이는 장식은 끌 수 있게
- **결정:** 눈·꽃잎·별·전구 깜빡임·후원 효과는 "움직이는 장식" 하나로 켜고 꺼요(기본 켬).
- **이유:** 방송 PC 사양이나 취향에 따라 움직임이 부담스러울 수 있어요. 효과는 CSS 애니메이션과 작은 요소 20여 개로 가볍게 만들었어요.

## G. 편집창

### D33. 편집창: 크게, 탭 3개, 열면 후원 입력부터
- **결정:**
  - 기본 1.3배로 키우고, 판 크기 배율을 올리면 같이 커지게 했어요.
  - 기능이 늘어 **후원 입력 / 화면 / 꾸미기** 탭으로 나눴어요.
  - 편집창을 열면 항상 후원 입력 탭이 먼저 보여요.
  - 새로 생긴 탭에는 한 번 열어 볼 때까지 NEW 표시가 떠요.
- **이유:** 방송 중 가장 많이 쓰는 건 후원 입력이에요. 한 화면에 다 넣으면 스크롤이 너무 길어져요. 편집창 크기는 OBS 소스 크기 안에서 계산해 잘리지 않게 했어요.

### D34. 제목·부제도 편집창에서 바꿈
- **결정:** 화면 탭에 제목·부제 입력칸을 두고, 바꾼 값은 D08 규칙으로 저장해요.
- **이유:** 방송 주제에 따라 제목만 바꾸고 싶은 경우가 많아요. 그때마다 파일을 다시 받는 건 번거로워요.

### D35. 새로 고침 아이콘과 직접 그린 말풍선
- **결정:** 판에 마우스를 올리면 오른쪽 위에 **새로 고침·편집 아이콘**이 크게 나와요. 편집창 맨 위에도 새로 고침 버튼이 있어요. 설명 말풍선은 브라우저 기본 툴팁(`title`)이 아니라 CSS로 직접 그려요.
- **이유:**
  - 새로 고침은 덮어쓰기 적용(D07)과 업데이트 확인(D25)의 입구라 잘 보여야 해요.
  - OBS 상호작용 창에서는 기본 툴팁이 안 뜰 수 있어요.
  - 마우스를 올렸을 때만 보여서 평소 방송 화면에는 안 나와요.

## H. 설정 페이지

### D36. 미리보기는 실제 현황판을 그대로 띄움
- **결정:** 미리보기는 배포된 현황판 템플릿에 지금 설정을 넣어 `iframe(srcdoc)`으로 띄워요. 게임 화면 배경 위에 판을 얹어 방송처럼 보여 줘요. 미리보기는 설정 페이지를 따라 내려와요.
- **이유:** "미리보기와 실제 파일이 다르다"는 문제가 원천적으로 생기지 않아요(D05).

### D37. 미리보기 예시 데이터
- **결정:**
  - 처음 들어오면 예시 표, "투표 불가 직업" 칩, "선호 직업" 칩, 하트를 보여 줘요.
  - 직업을 하나라도 고르면 예시는 모두 사라지고, 처음 설정으로 되돌리기 전까지 다시 안 떠요.
  - 예시는 미리보기에만 있고 받은 파일에는 들어가지 않아요.
- **이유:** 빈 판만 보면 투표 불가·선호가 어디에 어떻게 나오는지 알기 어려워요.

### D38. OBS / 프릭샷 선택
- **상황:** SOOP 스트리머 중에는 OBS 대신 SOOP의 **프릭샷 플러스**를 쓰는 분이 많았어요.
- **결정:** SOOP 공식 프릭샷 플러스 가이드(PDF 21쪽 "브라우저 소스 상호작용")로 확인했어요. 브라우저 소스에 **로컬 파일** 체크와 **상호작용** 버튼이 있어요. 그래서 설정 페이지에 "OBS를 사용해요 / 프릭샷을 사용해요"를 두고, 안내 문구를 바꿔 보여 줘요.

  | | OBS | 프릭샷 |
  |---|---|---|
  | 입력 창 열기 | 소스 우클릭 → 상호작용 | 소스 더블클릭 → 상호작용 버튼 |

- **이유:** 현황판 자체는 둘 다 같은 크롬 기반 브라우저 소스라 그대로 동작해요. 차이는 메뉴 위치뿐이라 안내만 나누면 돼요.

### D39. 맨 위 흐르는 직업 그림, 크기는 고정
- **결정:**
  - 메이플 이벤트 페이지처럼 직업 그림 48장이 왼쪽으로 흐르는 배경을 CSS 애니메이션으로 만들었어요. 그림은 한 장(`img/jobs.webp`)으로 합쳐 저장소에 넣었어요.
  - 두 시안 중 글자가 더 잘 읽히는 **A안**(어두운 바탕에 그림만)을 골랐어요.
  - 그림 띠 높이는 **690px로 고정**했어요.
- **이유:**
  - 외부 서버에서 불러오면 이벤트가 끝날 때 그림이 사라질 수 있어요.
  - 처음엔 띠 높이가 맨 위 칸 높이에 비례했어요. 그래서 "업데이트 내역", "업데이트 방법"을 펼칠 때마다 배경이 커졌고, 고정으로 해결했어요.

### D40. 2.0 소개: 맨 위 띠 + NEW 배지 + 기존 사용자 안내
- **결정:**
  - 맨 위 배너 아래에 **2.0 소개 띠**를 넣었어요. 감사 문구, 스킨 미리보기가 흐르는 줄, "스킨 구경하기", "업데이트 방법", 업데이트 내역이 들어 있어요.
  - 제목 옆에 NEW 2.0 배지를 달았어요.
  - "업데이트 방법"에는 버전별(v1.6 이상 / v1.5 이하) 안내를 넣었어요.
- **이유:** 기존 사용자에게는 "어떻게 받는지", 새 방문자에게는 "무엇이 좋아졌는지"가 필요해요.
- **버린 안:** 처음 방문 시 뜨는 소개 창(눈에는 띄지만 방문자에 따라 귀찮을 수 있어서 제외).

### D41. 건의하기: 구글 폼 + 공개 시트
- **결정:** 건의는 구글 폼으로 받고, 웹에 게시한 시트의 "공개" 탭(CSV)을 설정 페이지에서 읽어 목록으로 보여 줘요. 숨김과 답변은 시트에서 처리해요. 폼과 시트는 저장소 주인의 개인 계정이 아닌 별도 구글 계정 것이에요.
- **이유:** 서버 없이 "남의 건의도 보이는 게시판"을 만들 수 있어요. 관리자 기능(삭제·답변)은 구글 쪽 도구를 그대로 써요.
- **버린 안:** GitHub 로그인으로 사이트에서 바로 관리(정적 사이트에서 인증을 안전하게 처리하려면 서버가 필요함).

### D42. 맨 위 배너 문구
- **결정:** 어워즈 투표 응원 배너는 **조건 없는 부탁**으로만 써요("도움이 되었다면"). "투표하면 혜택" 같은 조건은 걸지 않아요. 배너는 주소가 비어 있거나 기한이 지나면 자동으로 숨겨지고, 숨긴 배너의 영상은 내려받지 않아요.
- **이유:** 대가성 투표 유도는 이벤트 규정에 어긋날 수 있어요.

## I. 보류하거나 하지 않은 것

### D43. 후원 자동 집계: 보류 (의사는 공개)
- **상황:** 가장 큰 사용자 가치지만 구조적인 부담이 있어요. 각 플랫폼 공식 문서로 확인한 내용이에요.

  | | 실시간 후원 받기 | 걸리는 점 |
  |---|---|---|
  | 치지직 | 가능. 금액·닉네임·후원 글이 옴 | 앱 등록 필요, 로그인 토큰을 계속 갱신해야 함 |
  | SOOP | 가능. 별풍선 개수·닉네임이 옴 | 후원 기능은 별도 심사, 별풍선 알림에 글이 없어 직업을 채팅과 맞춰야 함 |
  | 유튜브 | 슈퍼챗 조회 가능 | 하루 사용량 제한 |

  - 스트리머가 각자 앱을 등록하는 방식은 설정이 복잡해요.
  - 만든 사람이 앱 하나를 운영하는 방식은 비밀 키와 토큰을 지킬 **서버 운영**과 개인정보처리방침이 필요해요.
- **결정:** 지금은 "많이 써 주시면 개발해 볼 생각"까지만 밝혔어요. 만든다면 **치지직부터**, 그리고 완전 자동이 아니라 "후원이 목록에 뜨고 스트리머가 눌러서 확정"하는 방식을 생각하고 있어요.
- **이유:** 시청자가 "아란 말고 에반"처럼 쓰면 자동 판정이 자주 틀려요. 서버 없는 지금 구조(D02)와도 크게 달라져요.
